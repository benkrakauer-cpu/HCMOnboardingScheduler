HCM Onboarding Scheduler

Generate reviewable Outlook onboarding invitations — the system never sends anything.

OnboardingScheduler.BenjaminKrakauer.com

What it does

An internal web tool that prepares a new hire's onboarding meeting invitations. Staff assemble the meetings — individually or from a saved pattern — set the dates and times, and add the employee's email. Each meeting then opens in Outlook, pre-filled with attendees, time, location, and description. The system never sends anything — the HCM user adds a Teams link if needed, reviews, and sends from their own Outlook / O365.

How to use it

1Sign in

Enter the shared team password.

2Set up once

Add your Directory, Rooms, Meetings templates, and one or more Organizers.

3Build a pattern optional

Save a reusable meeting sequence with day offsets and times.

4Choose a mode

Manual (add meetings one by one) or Pattern (a saved sequence + a start date).

5Add hire & organizer

Type the username (@oem.nyc.gov added automatically); pick who sends.

6Tune the meetings

Date, time, duration, room or virtual, attendees, and optional daily/weekly repeat.

7Review warnings

NYC holidays and weekends are flagged for you to acknowledge.

8Generate

Each meeting appears as its own card. Every batch is saved to the Log.

9Open in Outlook

Opens pre-filled — add a Teams link if needed, review, and Send.

How it works

The app loads from S3 via CloudFront (TLS) and calls one Lambda through API Gateway. The Lambda validates the password and session token against Secrets Manager and reads/writes data in DynamoDB. Invitations are composed in the browser and opened directly in Outlook — the system stores data but never emails anyone.

Design note: invitations open directly in Outlook on the web rather than as downloaded .ics files, since new Outlook does not open local .ics files. The standards-compliant .ics generator remains in the codebase for classic-Outlook use.

Underlying technology

Frontend React single-page app (TypeScript) hosted on Amazon S3 behind CloudFront (private bucket, Origin Access Control), served over TLS.
Backend Amazon API Gateway (HTTP API) routing to a single AWS Lambda function (Node.js / TypeScript).
Data Amazon DynamoDB — one table, on-demand billing — holding the directory, meeting templates, rooms, patterns, organizers, and the generation log.
Access control AWS Secrets Manager stores the shared gate password and the session-token signing key. The Lambda verifies the password server-side and issues a short-lived signed session token.
Certificates / DNS AWS Certificate Manager (ACM) TLS certificate for the custom domain; DNS managed externally.
Infrastructure Defined as code with the AWS CDK (TypeScript). Region us-east-1, in an isolated AWS account.
Deliberate non-features: no Cognito, no SES / SMS, no Microsoft Graph or Teams API. Invitations are prepared for the user to review and send — the system sends no email and posts to no calendar on its own.

Access & security

  • Single shared password gate, intended for the HCM team's internal use.
  • The password is checked server-side in the Lambda against Secrets Manager — it is never shipped in the web app.
  • A successful sign-in returns a short-lived signed session token that authorizes each subsequent request.
  • Data table and hosting bucket are retained on teardown; the bucket is private (no public access).

What the system will not do

  • It never sends email. Every invitation is reviewed and sent by the user from their own Outlook / O365 account.
  • It does not connect to Microsoft 365, Teams, or any mail service.
  • It does not auto-book rooms or write to anyone's calendar.
  • All meeting times are handled in America/New York.
Core safety property. The Onboarding Scheduler is a preparation tool. It assembles and pre-fills onboarding meeting invitations; a person always performs the final review and the actual send. Nothing leaves the tool without an HCM staff member clicking Send in their own Outlook.
